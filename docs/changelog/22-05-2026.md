## 1.

Depois da limpeza de estilos, o `src/app.css` ficou com trechos inválidos:

- uma declaração solta `100%`;
- um seletor incompleto de botão Flowbite;
- blocos duplicados de `.header` e `.header-text`;
- referências antigas de fonte ainda espalhadas em estilos locais.

Isso causava erro no Tailwind/Vite:

```text
[plugin:@tailwindcss/vite:generate:serve] Invalid declaration: `100%`
```

Arquivo alterado:

- `src/app.css`

Mudanças:

- O arquivo foi reorganizado para remover CSS corrompido.
- A fonte global passou a ser definida por `--font-sans`.
- `html` e `body` passaram a usar a fonte global.
- `h1`, `.h1` e `p` passaram a usar a mesma variável de fonte.
- O CSS duplicado de `.header` e `.header-text` foi consolidado.

## 2.

Havia tentativa de trocar a fonte da aplicação para uma fonte do Google, mas alguns estilos ainda sobrescreviam a fonte diretamente, principalmente com `Inter`. As cores de fundo estavam hardcoded em classes como `bg-neutral-100` e em valores CSS como `#f5f5f5` e `#fff`. Isso dificultava manter um tema visual consistente.

Arquivos alterados:

- `src/app.css`
- `src/routes/+layout.svelte`
- `src/lib/components/sidebar.svelte`
- `src/routes/login/+page.svelte`
- `src/routes/registro/+page.svelte`
- `src/routes/settings/+page.svelte`

Mudanças:

- A fonte Google `Akt` foi importada no `src/app.css`.
- A variável `--font-sans` foi definida no `@theme`.
- Removidos `font-family: Inter` locais da página de configurações.
- O fundo principal das páginas passou a usar `bg-page`.
- O fundo do sidebar passou a usar `bg-surface`.
- O fundo dos headers passou a usar `var(--color-surface)`.
- Login e registro também passaram a usar `bg-page`.
- Criadas variáveis globais no `@theme`:

```css
--color-page: #f6f6f7;
--color-surface: #ffffff;
```

Exemplo atual:

```css
@import url('https://fonts.googleapis.com/css2?family=Akt:wght@400;500;600;700&display=swap');

@theme {
	--font-sans:
		'Akt', ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif;
}
```

## 3.

Cada página tinha um título (`h1`) e uma descrição (`p`), mas eles ficavam soltos dentro do conteúdo. Faltava um cabeçalho visual de dashboard ocupando toda a área entre a sidebar e a borda direita da tela.

Arquivos alterados:

- `src/app.css`
- `src/routes/clientes/+page.svelte`
- `src/routes/produtos/+page.svelte`
- `src/routes/usuarios/+page.svelte`
- `src/routes/settings/+page.svelte`
- `src/routes/infraestrutura/camaras/[id]/+page.svelte`

Mudanças:

- `.main-content > .header` e `.main-content > .header-text` agora renderizam como uma faixa branca no topo.
- O header ocupa a largura disponível do conteúdo principal.
- O header usa `bg-surface` via `var(--color-surface)`.
- Título e descrição ficam agrupados em `.header-text`.
- Páginas de clientes, produtos, usuários e configurações foram ajustadas para usar esse padrão.
- A página de detalhe de câmara também passou a usar `main-content`, `.header` e `.header-text`.
- O link "Voltar para Infraestrutura" foi movido para a área de ação à direita do header da página de detalhe da câmara (Isso será alterado).
