## Conversao de IDs para UUID PostgreSQL

As chaves primarias `id` das tabelas do modelo foram convertidas de inteiros sequenciais para `UUID` nativo do PostgreSQL com `DEFAULT gen_random_uuid()`. As chaves estrangeiras que apontam para esses IDs tambem passam a usar `UUID`, mantendo `epc_tag` como chave primaria textual de `LOTE_TAGGEADO`.

Arquivos alterados:

- `src/lib/server/schema.sql`
- `src/lib/server/database_manager.py`
- `src/lib/server/backend.server.py`
- `src/lib/server/auth.py`
- `src/lib/server/migrations/2026-05-31-convert-id-columns-to-uuid.sql`
- `src/routes/**`
- `docs/Modelagem de Dados.tex`

Mudancas implementadas:

- Substituidos `SERIAL` e `BIGSERIAL` por `UUID PRIMARY KEY DEFAULT gen_random_uuid()` nas tabelas com chave primaria `id`.
- Atualizadas colunas de relacionamento como `cliente_id`, `predio_id`, `camara_id`, `sensor_id`, `produto_tipo_id`, `leitura_bruta_id` e `movimentacao_id` para `UUID`.
- Removidas conversoes de IDs para inteiro nas rotas Flask, no blueprint de autenticacao e nas actions server-side do SvelteKit.
- Adicionada validacao de UUID no backend antes de executar consultas dependentes de identificadores.
- Atualizados tipos TypeScript das telas administrativas para tratar IDs como strings.
- Atualizada a documentacao de modelagem para refletir o novo tipo dos identificadores.
