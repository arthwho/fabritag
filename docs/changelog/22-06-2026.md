# Correções após a troca por UUIDs dos commits anteriores

Na página de infraestrutura o dispositivo continuava offline mesmo conectado ao servidor e enviando Heartbeat HTTP. ALém disso, ao tentar acessar a aba de Lotes na página de Produtos, a aplicação travava e parava de renderizar a UI.

Arquivos alterados:

- src/lib/server/database_manager.py
- src/routes/infraestrutura/+page.svelte
- src/routes/infraestrutura/InfraSensoresSection.svelte
- src/routes/produtos/+page.svelte

Problemas:

- O card principal da infraestrutura ainda lia sensorStore.liveStatuses['1'], enquanto o ping entrava no backend com a chave UUID. Pretendo alterar isso no futuro para facilitar a conexão do Microcontrolador com o sistema, utilizando outra chave, mas, por enquanto, ficará assim para evitar alterações no banco de dados próximo a etapa final do projeto de Iniciação Científica.
- Em /api/batches, depois dos UUIDs, produto_tipo_ids está chegando como string "{}" em vez de array. Ao clicar em “Lotes”, o template faz lote.produto_tipo_ids.join(', '); em string isso estoura erro JS e a UI para de renderizar.
- UUID[] estava vindo do psycopg2 como string ("{}"), e o código tratava como lista.

Mudancas implementadas:

- Na tela de infraestrutura foi trocado lookup fixo ['1'] por UUIDs reais dos sensores.
- O card agora escolhe qualquer dispositivo online vindo do backend, ou o primeiro sensor cadastrado como fallback.
- UUIDs convertido para TEXT[] na query.
- Renderização da aba “Lotes” agora tolerante a produto_tipo_ids vindo como array, string vazia ou "{}".
